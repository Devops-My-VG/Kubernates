📌 Overview

This document provides comprehensive documentation for the professional GitLab CI/CD pipeline implementation for ECS cluster infrastructure. The pipeline automates Terraform deployments across multiple environments with strict controls and best practices.

Key Features

  • Multi-Environment Support: INT, QA, STG, PRD
  • Standard 4-Stage Pipeline: Validate → Plan → Apply → Destroy
  • Production Safety: Manual approvals for sensitive operations
  • Centralized State Management: S3 backend with Object Lock
  • Dynamic Configuration: Environment-specific tfvars
  • Security First: AWS credentials via CI/CD variables

🏗️ Architecture

Design Philosophy

  • Multi-Environment: Separate infrastructure for each tier
  • Standard Pattern: Industry-standard 4-stage pipeline
  • Separation of Concerns: Same stages, different configurations
  • Production Safety: PRD at end with manual approval
  • State Consistency: Centralized S3 backend with locking

⚙️ Pipeline Structure

Stages Definition

stages:
  - validate    # Syntax validation and format checks
  - plan        # Terraform plan for all environments
  - apply       # Terraform apply (manual trigger)
  - destroy     # Terraform destroy (manual trigger)

Validate Stage

Ensures Terraform configuration is properly formatted and syntactically valid.

validate:
  stage: validate
  image: ubuntu:22.04
  script:
    - ./terraform fmt -check -recursive .
    - ./terraform validate
  rules:
    - if: '$CI_PIPELINE_SOURCE == "schedule"'
      when: never
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
    - if: '$CI_COMMIT_BRANCH == "main"'
Property Value
Purpose Syntax validation and format checks
Trigger Automatic on merge requests and main branch
Duration ~30-60 seconds

Plan Jobs (INT, QA, STG, PRD)

Generate execution plans for each environment without making changes.

plan:int:
  stage: plan
  image: ubuntu:22.04
  environment:
    name: INT
    deployment_tier: development
  script:
    - ./terraform plan -var-file="environments/int.tfvars" -out=tfplan.int
    - ./terraform show -no-color tfplan.int > plan_output_int.txt
  artifacts:
    paths:
      - tfplan.int
      - plan_output_int.txt
      - .terraform.lock.hcl
    expire_in: 7 days
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
Property Value
Purpose Generate execution plans for each environment
Trigger Automatic on main branch
Artifacts Saved plan files for apply stage
Duration ~1-2 minutes per environment

Apply Jobs (INT, QA, STG, PRD)

Execute Terraform changes to create/update infrastructure.

Property Value
Purpose Execute Terraform changes
Trigger Manual (requires user approval)
Dependencies Requires successful plan job
Duration ~2-5 minutes per environment

Destroy Jobs (INT, QA, STG, PRD)

Teardown infrastructure (typically for development/testing).

Property Value
Purpose Teardown infrastructure
Trigger Manual (requires explicit approval)
Use Cases Development cleanup, cost savings
Duration ~1-3 minutes per environment

Backend Initialization

before_script:
  - cd ${TF_ROOT}
  - apt-get update -qq && apt-get install -y -qq curl unzip ca-certificates
  - curl -fsSLo terraform.zip "https://releases.hashicorp.com/terraform/1.16.2/terraform_1.16.2_linux_amd64.zip"
  - unzip -q terraform.zip && rm -f terraform.zip && chmod +x terraform
  - ./terraform version
  - ': "${CI_ENVIRONMENT_NAME:?ERROR - CI_ENVIRONMENT_NAME is not set}"'
  - export TF_STATE_ENV="$(printf '%s' "${CI_ENVIRONMENT_NAME}" | tr '[:upper:]' '[:lower:]')"
  - ./terraform init -backend-config="bucket=bucket-s3-infra-devops" -backend-config="key=ecs-cluster/${TF_STATE_ENV}/terraform.tfstate" -backend-config="region=${AWS_DEFAULT_REGION}" -backend-config="encrypt=true" -backend-config="use_lockfile=true"

✅ Prerequisites

AWS Account Setup

  1. Create S3 Bucket: 
    aws s3api create-bucket \
  --bucket bucket-s3-infra-devops \
  --region us-east-1
  2. Enable Versioning: 
    aws s3api put-bucket-versioning \
  --bucket bucket-s3-infra-devops \
  --versioning-configuration Status=Enabled
  3. Enable Encryption: 
    aws s3api put-bucket-encryption \
  --bucket bucket-s3-infra-devops \
  --server-side-encryption-configuration '{"Rules": [{"ApplyServerSideEncryptionByDefault": {"SSEAlgorithm": "AES256"}}]}'
  4. Create IAM User: gitlab-cicd-deployer with S3 and EC2 permissions
  5. Generate Credentials: AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY

GitLab Setup

  • Install and register GitLab Runner
  • Add AWS credentials to CI/CD variables
  • Ensure runner has repository access

Local Requirements

  • Terraform >= 1.16.2
  • AWS CLI v2
  • Git
  • Bash shell

▶️ Pipeline Execution

Manual Pipeline Trigger

  1. Go to: GitLab → Project → CI/CD → Pipelines
  2. Click: "New Pipeline"
  3. Select Branch: "main"
  4. Click: "Create Pipeline"

Execution Flow

Commit to main ↓ validate job starts (automatic) ↓ validate passes? ├─ YES → plan jobs start (automatic, parallel) │ ↓ │ plan jobs complete │ ↓ │ apply jobs ready (manual, waiting for approval) │ └─ NO → Pipeline failed, check logs

Monitoring Pipeline Status

  • View pipeline in GitLab UI
  • Each job shows status, duration, logs, and artifacts
  • Click job name to view detailed logs

🔒 Security Considerations

Secrets Management

Important: AWS credentials are stored in GitLab CI/CD Variables (encrypted). Never commit credentials to repository.

Access Control

  • GitLab Permissions: Protected main branch, developers can trigger manual jobs
  • AWS IAM: Least privilege principle with service-specific policies
  • Audit Trail: All actions logged in GitLab and AWS

State File Protection

  • S3 backend with AES-256 encryption
  • Object Lock enabled for state consistency
  • Versioning enabled for recovery

🐛 Troubleshooting

Issue 1: CI_ENVIRONMENT_NAME Not Set

Error: ERROR - CI_ENVIRONMENT_NAME is not set

Cause: Job doesn't have environment: block

Solution: Add environment block to job definition:

environment:
  name: INT
  deployment_tier: development

Issue 2: S3 State File Error (Double Slash)

Error: Value must not contain "//"

Cause: Environment variable empty, resulting in double slash

Debug: Check environment variable output in job logs

Issue 3: VPC Limit Exceeded

Error: Error: creating EC2 VPC, ... VpcLimitExceeded

Solution:

  1. Delete unused VPCs in AWS Console
  2. Request AWS limit increase
  3. Use Service Quotas console

Issue 4: Undeclared Variable Warning

Warning: Value for undeclared variable "aws_profile"

Solution: Remove from terraform.tfvars file

Debugging Tips

  • View job logs in GitLab UI
  • Check S3 state files: aws s3 ls s3://bucket-s3-infra-devops/
  • Enable TF debug: export TF_LOG=DEBUG

⭐ Best Practices

Pipeline Management

  • Protect main branch with merge request reviews
  • Always progress through environments: INT → QA → STG → PRD
  • Keep documentation updated with variable changes
  • Maintain deployment runbooks

Terraform Best Practices

  • Format code: terraform fmt -recursive .
  • Validate syntax: terraform validate
  • Use descriptive variable names with validation rules
  • Never manually edit state files
  • Always use remote state

Deployment Strategy

  • Always run plan first and review output
  • Test in INT environment before other environments
  • Start with small changes to validate process
  • Keep previous state versions for rollback

Team Workflow

  • Require code review before merging
  • Announce deployments to team
  • Document all changes and decisions
  • Share lessons learned from issues
