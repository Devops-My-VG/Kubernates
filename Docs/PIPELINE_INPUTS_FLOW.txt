🔄 STEP-BY-STEP INPUT PROCESS
════════════════════════════════════════════════════════════════════════════════

STEP 1: Create AWS IAM User
────────────────────────────
  aws iam create-user --user-name ecommerce-app-deployment
  ↓ Get AccessKeyId and SecretAccessKey
  ↓ Save these securely
  

STEP 2: Run Collection Script (provided)
───────────────────────────────────────
  ./collect-inputs.sh
  ↓ Displays all infrastructure values
  ↓ Copy output


STEP 3: Get Database/Cache Credentials
────────────────────────────────────────
  aws secretsmanager get-secret-value --secret-id ecs-cluster-int/rds/master-password
  aws secretsmanager get-secret-value --secret-id ecs-cluster-int/redis/auth-token
  ↓ Copy host, port, password values


STEP 4: Generate Application Secrets
──────────────────────────────────────
  openssl rand -base64 32  (for JWT_SECRET)
  ↓ Copy generated value


STEP 5: Open GitLab Settings
──────────────────────────────
  GitLab → Project → Settings → CI/CD → Variables
  ↓ Click "Add Variable"


STEP 6: Add Each Variable
──────────────────────────
  For each of 20+ variables:
    1. Key: [Variable name]
    2. Value: [Value from steps 1-4]
    3. Protected: ✅ (all)
    4. Masked: ✅ (secrets only)
    5. Click "Add variable"
  

STEP 7: Trigger Pipeline
────────────────────────
  Push code to GitLab
  ↓ Pipeline automatically starts
  ↓ Uses your variables


STEP 8: Monitor Deployment
──────────────────────────
  GitLab → CI/CD → Pipelines
  ↓ Watch pipeline stages
  ↓ Check CloudWatch logs


STEP 9: Verify Application
──────────────────────────
  Get ALB DNS: aws elbv2 describe-load-balancers ...
  ↓ Open: http://[ALB_DNS]
  ↓ Application running ✅

Problem                      Solution
────────────────────────────────────────────────────────────────────────────

"ALB returning 502"          Verify health check path in task definition
"No logs in CloudWatch"      Check IAM task execution role has CloudWatch perms
